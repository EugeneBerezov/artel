## 3. New behaviour in the minimum (spec changes)

### 3.1 Verify rerun on red (T33)

- Setting `verify_reruns` (int, default 1, min 0). Applies to **task verify
  only**; a red **base-update** verify is not rerun (it pauses the board as
  today and the human looks).
- Red (non-zero exit, not a timeout) → rerun the whole verify once on the same
  merged tree under the heavy lock, without `setup`. Timeout → no rerun.
- Rerun green → the task is treated as green **but flagged** `flaky`: its
  merge becomes `ask` (it waits for the human in `awaiting_accept`, with the
  red log attached). A flaky green never auto-merges. Rerun red → red as
  today.
- Recorded as a `runs` row (stage `verify`, `n` = attempt, outcome
  `red|green`, duration) and a runner **FAIL** entry `flaky verify: <cmd>`,
  never FACT (FACT entries are fed to later agents and would teach them to
  dismiss failures — attack 2, #3).
- More than 2 flaky verifies in 24 h → pause `flaky` and notify.

Rationale: a race an agent introduced that fails 30 % of the time would be
auto-merged with p = 0.91 instead of 0.70 under a silent rerun; with "flaky →
ask" it never auto-merges, and real flakes cost the human a click instead of
an agent attempt.

### 3.2 Night circuit breakers (T33) — replaces the v1 ref guard

The v1 ref-only guard is dropped (attack 1 #2, attack 2 #2: it watched
`main`, which git already protects; it missed `artel/*`, config, hooks and
the board; it fired on every controller merge). Protection comes from the
dedicated clone (§4) plus:

- **Consecutive-failure breaker:** 3 failed agent stages in a row across the
  board (fail, invalid result, timeout, internal error) → pause
  `failures` + notify.
- **Per-task lifetime cap:** `max_stage_runs` (default 12) agent runs per task
  over its life → `stuck` with a VERDICT naming the setting. Closes the
  write/verify/fix loop that PD-49's attempts reset would otherwise allow.
- **Quota guard:** stop taking new stages when the reported utilization of
  any window (`rate_limit_event.unifiedWindows.{five_hour,seven_day}.utilization`,
  spike Q2) is ≥ `quota_stop` (default 0.9), independent of `limit_stop`'s
  status rank; pause until that window's `resetsAt`.
- **Limit pause without reset time** (PD-40): re-check every
  `limit_retry` (default 30 min) with one cheap probe stage instead of
  waiting for a human; at most 4 probes per night, then wait (owner, §8 Q-C).

## 4. Phase 2 — artel builds artel, in a dedicated clone

- **Dedicated clone** `~/artel-dogfood` (outside this checkout): its own
  `.git`, so its board, slots and refs cannot touch the s1/s2/controller
  state; remote without push credentials. The controller pulls
  `artel/integration` from it into a branch of this repository, reviews,
  runs CI, merges into `main`.
- artel runs from `artel.pyz` built from a tagged `main` commit; upgrading
  is an explicit controller step (stop runner → rebuild → start). Prompts
  and templates then cannot change mid-run.
- Agents run with `--setting-sources project,local` **unless T16 shows that
  breaks auth or tools** (it keeps `~/.claude` hooks, skills and CLAUDE.md
  out of agent stages).
- Tasks: `artel add` per phase 2 plan task — title = plan heading; body =
  "Implement docs/plan.md 'Task N: <heading>'; read only that section, Global
  Constraints and the PDs it cites"; `--area` = its Files; plan
  dependencies **plus the shared-file order** (areas prevent overlap, not
  order); `--strong` for RISKY. `merge = auto` (T32 now forces `ask` on
  protected paths; a general `ask` would block dependent chains).
- Research backlog after the gate, ranked: review-outcome logging;
  fail-before/pass-after for `bugfix` tasks; reviewer probe tests; pre-merge
  hook point; `.worktreeinclude`.
- s1/s2 retire at the gate; fallback if artel breaks itself: the controller
  restarts s1/s2 on `main`.

## 6. Benchmark — scaled to this machine and quota

Facts (attack 1 #4, verified): no docker, 12 GB free disk → SWE-bench
evaluation cannot run here. Last night ≈ 420 M tokens for ≈ 15 tasks; five
systems × 50 tasks ≈ 3–8 such nights. N = 50 paired detects only ≈ 18-point
differences; 10 points needs ≈ 200 tasks.

Proposal:
- **Task set:** a purpose-built multi-task repository (30–40 tasks with
  hidden acceptance tests written before the run, some tasks interacting
  through shared code) — the setting artel is for, and free of training-set
  contamination.
- **Stage 1:** artel vs one plain Claude Code session (same model, same
  permission mode, same quota window).
- **Stage 2:** artel ablations: fresh reviewer vs writer self-review (review
  cannot be turned off — PD-51), merged-tree verify vs branch verify, verify
  rerun on/off.
- **Stage 3:** models per role.
- DeLM: not in the first stages (no Mac at hand). Agent teams and Claude Squad:
  agent teams do not run in `-p`; Squad adds nothing over a plain session.
- Controls: pin model versions, record CLI version, same prompts budget,
  report variance over ≥ 2 seeds for a subset.
- Claims are framed as effect sizes with intervals, not "better".
