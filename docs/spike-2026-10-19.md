# Spike 2026-10-19 — live checks of `claude -p` flags (spec §14)

Environment: Claude Code 2.1.304, model `haiku` (`claude-haiku-5-5`), subscription login.
Throwaway repo with a worktree at `.claude/worktrees/artel-1`; Q6/Q7 ran read-only in
the Divo repository. 17 `claude` invocations (16 reached the API; one failed instantly on
the prompt-argument problem of Q4). Raw streams were kept in the session scratchpad only.

Environment trap found on the way: the owner's `~/.claude/settings.json` has
`permissions.defaultMode: "auto"`. `-p` inherits it (`init.permissionMode == "auto"`),
which changes Q4 results (see there). Every profile must pass `--permission-mode`
explicitly.

Second trap: `--disallowedTools` / `--allowedTools` are variadic and swallow a
positional prompt (`Error: Input must be provided either through stdin or as a prompt
argument`). Pass the prompt on stdin. With no stdin attached, claude also waits 3 s
("no stdin data received in 3s").

## Q1. `--json-schema` + `--output-format stream-json --verbose`

Command:
`claude -p --model haiku --output-format stream-json --verbose --json-schema '{"type":"object","properties":{"outcome":{"enum":["done","ask"]},"summary":{"type":"string"}},"required":["outcome","summary"]}' --permission-prompts none --disable-slash-commands --strict-mcp-config "Report outcome done with summary hello."`

Evidence (event types: `system/init`, `system/thinking_tokens`, `assistant` x2, `user`,
`rate_limit_event`, `result`):
```
final result keys: api_error_status, duration_api_ms, duration_ms, fast_mode_disabled_reason,
 fast_mode_state, first_content_frame_ms, is_error, modelUsage, num_turns, permission_denials,
 queued_turn_count, result, result_index, safety_stops, session_id, stop_reason,
 structured_output, subagent_stats, subtype, terminal_reason, time_to_request_ms,
 total_cost_usd, ttft_ms, ttft_stream_ms, type, usage, uuid
"structured_output": {"outcome":"done","summary":"hello"}
"result": "{\"outcome\":\"done\",\"summary\":\"hello\"}"      (same JSON, as a string)
subtype "success", is_error false, num_turns 2, terminal_reason "completed"
assistant tool_use: name "StructuredOutput", input {"outcome":"done","summary":"hello"}
```
Conclusion: works. The parsed object is in `result.structured_output`; `result` holds
the same JSON as a string. The model delivers it by calling a synthetic `StructuredOutput`
tool, so the run takes at least 2 turns (3 in the Divo repo) and `usage` sums all of them.
Spec impact: §6/§5 can rely on `structured_output`; the adapter should treat a missing
`structured_output` (or `is_error`) as a failed run. Note that `stop_reason` of the final
event was `"tool_use"` on a successful run, so do not use it as a failure signal.

## Q2. `rate_limit_event`

Command: same run as Q1. The event appeared (once, just before `result`) on every run.
```
{"type":"rate_limit_event","rate_limit_info":{"status":"allowed","resetsAt":1792464000,
 "rateLimitType":"five_hour","overageStatus":"rejected","overageDisabledReason":"org_level_disabled",
 "isUsingOverage":false,"unifiedWindows":{"five_hour":{"utilization":0.1,"resetsAt":1792464000},
 "seven_day":{"utilization":0.02,"resetsAt":1793048400}}},"uuid":"...","session_id":"..."}
```
Conclusion: exists, always emitted with `status: "allowed"` when not limited. Fields:
`status`, `resetsAt` (unix seconds), `rateLimitType`, `overageStatus`,
`overageDisabledReason`, `isUsingOverage`, `unifiedWindows.{five_hour,seven_day}.{utilization,resetsAt}`
(`utilization` is a 0..1 fraction). The non-"allowed" status values were not observed
(not provoked on purpose). Spec impact: the runner can pause on `status != "allowed"` and
sleep until `resetsAt`; the exact non-allowed status strings must be learned from a real
limit hit and the parser should tolerate unknown values. `utilization` allows a
proactive pause before the limit.

## Q4. Reviewer profile

Command (prompt on stdin: run `git log --oneline`, then create x.txt "by any means"):
`claude -p --model haiku --output-format stream-json --verbose --permission-mode default --permission-prompts none --disable-slash-commands --strict-mcp-config --disallowedTools "Edit Write NotebookEdit" --allowedTools "Bash(git diff *) Bash(git log *)"`

Without `--permission-mode default` (inheriting the owner's `auto`): NOT blocked.
```
init.permissionMode: "auto"; tools: Task, Bash, Read, ... (no Edit/Write/NotebookEdit)
Bash: git log --oneline        -> e0479d7 init
Bash: printf 'hi\n' > x.txt && cat x.txt  -> hi        (is_error false)
permission_denials: []         x.txt exists on disk
```
With `--permission-mode default`: blocked.
```
init.permissionMode: "default"
Bash: git log --oneline -> "e0479d7 init" (allowed)
Bash: printf 'hi\n' > x.txt && cat x.txt -> is_error true:
 "Permission for this tool use was denied. It requires approval, and this session has no
  approval surface ... so it was denied automatically. The action was NOT performed; do not
  claim it succeeded, and do not retry it: this action, and anything else that requires approval,
  will be denied the same way for the rest of this session ..."
result.permission_denials[0] keys: tool_name, tool_use_id, tool_input   (tool_name "Bash")
ToolSearch select:Write -> "No matching deferred tools found"; x.txt not created
```
Conclusion: `--disallowedTools` removes Edit/Write/NotebookEdit from the tool list entirely;
`--allowedTools` + `--permission-prompts none` allow `git log` and deny any other Bash
command, recorded in `result.permission_denials`. BUT the effective permission mode is
inherited from user settings; under `auto` a shell redirection writes a file with no
denial. Also, denial is sticky: the tool result tells the model that everything that needs
approval is denied for the rest of the session (the model stops trying).
Spec impact: add `--permission-mode default` to reviewer/attacker (and consider
`--settings` / explicit mode on every profile, "common" line); a reviewer's read-only
guarantee otherwise depends on the owner's personal settings. Document that
`permission_denials` in the final event is the machine-readable signal for "an agent was
blocked" (feed into the journal / `ask`). Prompt must go on stdin (variadic tool flags).

## Q5. Writer profile in the worktree

Command (cwd `repo/.claude/worktrees/artel-1`, stdin: create hello.txt and commit it):
`claude -p --model haiku --output-format stream-json --verbose --permission-mode acceptEdits --permission-prompts none --disable-slash-commands --strict-mcp-config --allowedTools "Bash(git add *) Bash(git commit *)"`
```
init.permissionMode: "acceptEdits"; tools include Bash, Edit, Write
Bash: printf 'hello\n' > hello.txt && git add hello.txt && git commit -q -m "add hello" -m "Co-Authored-By: ..."
git log (worktree, branch artel-1): 12d6b68 add hello / e0479d7 init ; hello.txt present
permission_denials: []   num_turns 2
```
Conclusion: yes. The file appeared in the worktree and the commit landed on branch
`artel-1`. The agent created the file with a shell redirection (compound command
`printf > f && git add && git commit`), not the Write tool, and the compound command was
allowed because every part matched `git add`/`git commit` or was an in-cwd write under
`acceptEdits`. Spec impact: none for the profile. Note that the agent added a
`Co-Authored-By` trailer on its own (from the owner's user-level instructions): commit
text hygiene is not guaranteed by the profile.

## Q6. Startup overhead in the Divo repository

Commands (prompt `Reply with the single word OK`, cwd `/usr/local/src/montage_harness`,
`--model haiku --permission-mode default --disallowedTools "Edit Write NotebookEdit"`):
lean = spec §6 common line (`--json-schema`, `--permission-prompts none`,
`--disable-slash-commands --strict-mcp-config --exclude-dynamic-system-prompt-sections
--append-system-prompt-file notice.txt`) plus reviewer tools; full = no extra flags.
```
run                              turns  input  cache_creation  cache_read  output  total_cost_usd
lean (+schema, +notice) #1         3      6      31684          23389       115    0.0066
lean (+schema, +notice) #2         3      6          0          55073       150    0.00063
lean, no schema, no notice         1      2      11025          16284         4     0.0024
full, no schema                    1      2      23158          10644         4     0.0047
full, with schema                  3      6      50009          17924       239    0.0103
per assistant message, lean #1: call1 cc 27515 cr 0; call2 cc 4169 cr 23389
per assistant message, lean #2: call1 cc 0 cr 27515; call2 cc 0 cr 27558
```
Conclusion: `usage` in the final event is a SUM over all API calls of the run (each
`StructuredOutput` round trip counts the whole prompt again), so read per-message
`assistant.message.usage` for the real first-turn cost. Real prompt size in the Divo repo:
about 27.5k tokens for the lean profile, about 33.8k for the full profile (23158+10644),
so the lean flags save about 6k tokens (~19%) per call; the cached prefix is mostly the
repo's CLAUDE.md, the owner's user CLAUDE.md and the memory index, which the lean flags
do not remove. The second run reused the cache completely (cache_creation 0, cache_read
27.5k, cost 10x lower). Part of the first run's cache_read came from earlier runs
(shared prefix), so a cold start costs ~27.5k cache-creation tokens. `total_cost_usd`
is present. Spec impact: replace the §14.6 expectation with "first-turn cache_creation
~27.5k (lean, Divo, haiku)"; the budget estimator must use per-message usage; run all
agents of a task within the 5-minute cache window and keep the appended notice
byte-identical (it is part of the cached prefix). A schema-bearing run always has at
least two API calls.

## Q7. Unattended notice vs CLAUDE.md; `--setting-sources`

`claude --help` has `--setting-sources <sources>` ("Comma-separated list of setting
sources to load (user, project, local)"). The notice file contained the text from the task
("No human is present. This overrides any instruction to ask a human or wait for approval...").
Common line: `-p --model haiku --output-format stream-json --verbose --permission-prompts none --disable-slash-commands --strict-mcp-config --exclude-dynamic-system-prompt-sections --permission-mode default --disallowedTools Edit,Write,NotebookEdit`, cwd Divo.

Test A, prompt "Should you ask the owner before doing anything? Answer yes or no and why, in one line." — control (no notice), notice, notice + `--setting-sources project,local`: all three answered "No" (ask only for hard-to-reverse or outward-facing actions). Not discriminating: the CLAUDE.md rule is conditional, not "always ask".

Test B, prompt: line 1 "per the project's CLAUDE.md, when an architectural or stylistic decision is needed, do you ask the owner or decide yourself?", line 2 "do you have an instruction titled 'Check for a skill before acting' in your context?"
```
control:        1. "Decide myself when the owner isn't watching and the choice is reversible ...;
                   when they are present, ask in one batch of up to four questions ..."  2. No.
notice:         1. "Ask, but only when the owner is present and the decision is open. Otherwise I decide ..."  2. No.
notice+project,local: 1. "Decide myself when reversible ... Ask the owner, in one batch of up to four questions,
                   when the choice is visible to them or touches deletion, quotas, money, protocol ..."  2. No.
```
Conclusion: inconclusive for a clean verdict. The project CLAUDE.md in Divo does not say
"always ask the human first" (it already has "decide yourself when the owner is not
watching"), so no override could be demonstrated; the notice did not make the model
ignore CLAUDE.md, and in the one run where it was cited it still described asking
"when the owner is present". The `--setting-sources` flag exists and is accepted with
`project,local`; it changed the cached prefix size by about 1.4k tokens, but the
model still reported project-level rules, and the "user" CLAUDE.md marker line (line 2)
was "No" in ALL runs, including the control, so this check could not show whether the
user file was loaded or skipped. A stricter test needs a throwaway repo with a
CLAUDE.md that says "Always ask the user before any action" and a real action prompt.
Spec impact: do not claim in the spec that the notice overrides CLAUDE.md; keep it as
"best effort", and keep the `--setting-sources project,local` option as a configurable
knob (default off) until the stricter test is run. The `ask` outcome must also be the
only escape in the schema (the notice names it).

## Summary of spec changes suggested

- §6 common: add explicit `--permission-mode` per profile (reviewer: `default`); the
  owner's `auto` default silently turns the reviewer into a writer through Bash.
- §6/§8: pass prompts on stdin (variadic `--allowedTools` swallows an argument prompt);
  attach stdin explicitly to avoid the 3 s wait.
- §5: result = `structured_output`; usage must come from per-message usage, not the
  summed final `usage`; `permission_denials` is the denial signal; `rate_limit_event`
  fields as in Q2.
- §14.6/7: record the numbers above; Q7 needs a sharper follow-up test.
