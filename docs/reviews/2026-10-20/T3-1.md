# T3 controller review #1 (merge ad15e83) — verdict: FAIL (reopened)

Sources: CI run 39344439863 + independent opus review. Close every blocker/major.

## Blocker
- CI red on ubuntu-latest/3.13: tests/test_platform.py:141 test_soft_terminate_runs_callback.
  `install_stop_handlers` runs the callback inside the signal handler (platform.py:293);
  the signal arrived while main was inside print('up') -> callback's print raises
  `RuntimeError: reentrant call inside BufferedWriter`. Design fix: the handler only
  records the stop (flag / threading.Event / os.write of one byte to a self-pipe);
  the callback runs outside signal context (e.g. the runner polls; or a helper
  `wait_for_stop`). Test must not depend on print timing.

## Major
1. terminate_tree never cleans up when the leader is gone but children live
   (platform.py:241,260,270-272). Linux zombie leader -> fingerprint None; reaped
   leader -> None; Windows pid_alive False -> None; all return False before any signal.
   Scenario: verify `sh -c "npm test"`; sh exits leaving a server holding stdout;
   timeout fires; nothing killed; pipe never closes; run_tree (T8) hangs.
   Windows: job handle stays in _JOBS forever (one leak per stage), orphans live.
   Fix: POSIX killpg(group) whenever tree_alive(group) even without leader
   (a pgid cannot be reused while the group exists); Windows terminate the job object
   and close/remove its handle. Spec §5 reconcile "terminates process groups".
2. macOS waits the full kill_grace every time (platform.py:230-236,280): _not_zombie
   returns True without /proc; an unreaped leader keeps killpg(g,0) succeeding, so each
   timeout blocks 30 s even if the agent exits on SIGTERM. pid_alive True for zombies
   on macOS. Fix: `ps -o stat= -p PID` (Z = zombie) on macOS.
3. Windows shell="cmd" breaks commands with quotes (platform.py:343): list2cmdline
   gives `cmd /d /s /c "echo \"a b\""`; cmd does not understand \". Build the
   cmd command line by hand (/s /c "<command>" with the command passed verbatim) and
   test execution (not just argv shape) on Windows.
4. .cmd shim/wrapper written as UTF-8, but cmd.exe reads batch files in the OEM code
   page (platform.py:357,365,380): a Cyrillic user profile path breaks artel.cmd; `%`
   in a baked path is expanded. Fix: write with `chcp 65001 >nul` first line or
   encode in the OEM code page; escape `%` as `%%`. SPEC-GAP note (plan says utf-8).
