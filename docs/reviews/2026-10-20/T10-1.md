## Blocker 1 (all OSes): setup tests fail under the CI child-encoding env (T28)
SetupTest.counter_cmd (tests/test_slots.py ~551) runs `py_cmd("open(<path>, 'a').write('x')")` — open() without
encoding in a CHILD; CI sets PYTHONWARNDEFAULTENCODING=1 + PYTHONWARNINGS=error::EncodingWarning, so the setup
child dies and run_setup_if_needed returns 'failed'. Reproduce locally:
  PYTHONWARNDEFAULTENCODING=1 PYTHONWARNINGS=error::EncodingWarning python3 -m unittest tests.test_slots  -> 5 failures
Fix: encoding='utf-8' in every py_cmd code string (grep tests for `open(` inside py_cmd/f-strings). Always run the
suite locally with those two env vars before integrate.
Failing: test_recreated_slot_forgets_its_setup_hash, test_setup_env_is_passed, test_setup_reruns_when_an_input_changes,
test_setup_runs_under_heavy_prefix, test_setup_skipped_when_hash_unchanged.
## Blocker 2 (Windows only): test_guard_refuses_a_git_file_pointing_at_a_users_worktree (test_slots.py:371)
`(slot/".git").write_text(...)` -> PermissionError: Git for Windows marks a worktree's `.git` file HIDDEN; opening a
hidden file with mode 'w' (CREATE_ALWAYS) is denied. Fix the test: unlink the file first, then write (or clear the
hidden attribute via platform). Also check production code never rewrites a .git file in place on Windows.
