## Blocker
- CI red on windows-latest/3.13 (run 39348116259):
  tests.test_board.BoardTest.test_concurrent_first_open_creates_one_schema
  `[BoardBusy('database is locked'), BoardBusy(...), '1', '1'] != ['1','1','1','1']`.
  Cause (likely): `PRAGMA journal_mode=WAL` (and the first schema creation) on a fresh db
  with concurrent connections returns SQLITE_BUSY without invoking the busy handler
  (journal-mode change needs an exclusive lock; SQLite skips the busy handler when it could
  deadlock), so busy_timeout does not help and the code maps it straight to BoardBusy.
  Fix: in open_board, retry the journal-mode pragma and the schema creation on "locked"
  with a deadline = busy_timeout_ms (short sleeps), only then raise BoardBusy; or serialize
  first-time creation with a BEGIN IMMEDIATE before reading/setting the mode. Keep the test
  (it is right); maybe raise threads to 8 to make it bite on Linux too.
