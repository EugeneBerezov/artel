# T3 controller note #3 — flaky test on Windows (reopened)
CI run 39357040578 (merge c1d462f, unrelated T11 change), windows-latest/3.11:
tests.test_platform.TreeTest.test_tree_alive_false_after_exit — `AssertionError: True is not false`.
Windows tree_alive asks the job's ActiveProcesses; right after the leader exits the job can still
count it (or a conhost child) for a moment. Fix: the test waits for tree_alive to become False with a
deadline (e.g. 10 s, poll 50 ms) instead of asserting immediately; if production callers (T8 run_tree,
T22 reconcile) rely on an immediate False, make tree_alive itself robust (ignore processes that have
exited / give the job a short settle). Also re-check other tests that assert an immediate post-exit state
(earlier flakes: test_terminate_tree_kills_grandchild on ubuntu).
